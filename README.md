# tmem — 翻译记忆检索库

Go 实现的翻译记忆（Translation Memory）检索模块，以库的形式供上层文档翻译服务
调用（无接口层）。数据持久化在调用方指定的本地目录，仅依赖 Go 标准库，
适用于物理隔离网环境。

## 功能

- 按语言对（`Pair{Source, Target}`，语言代码按原样区分）组织条目，检索只在同一语言对内进行。
- 写入与检索文本先规范化：连续 Unicode 空白（含不换行空格、全角空格）合并为一个半角
  空格并去首尾空白；规范化后为空、超过 1000 码点或非法 UTF-8 一律拒收。
- 同一语言对内规范化原文相同的为同一条目；批写入原子生效，批内重复以靠后者为准，
  再次写入以最后一次为准（覆盖译文、原文原样、完成时间）。
- 相似度 = `floor(100*(m-d)/m)`，`d` 为码点级编辑距离，`m` 为较长段码点长度。
- 检索按相似度降序、最后写入时间降序、规范化原文码点序排列，支持门槛（75~100，
  默认 75）与条数上限（1~50，默认 5）。
- 清理删除最后写入时间早于当前时刻 180 天的条目（正好 180 天的保留）。
- 写入返回即可检索；清理返回后被删条目不再出现。

## 用法

```go
s, err := tmem.Open("/var/lib/myapp/tmem") // 目录由调用方指定
if err != nil { /* ... */ }

err = s.WriteBatch(tmem.Pair{Source: "en", Target: "es"}, []tmem.Entry{
    {Source: "The Parties shall …", Target: "Las Partes deberán …", CompletedAt: time.Now()},
})

hits, err := s.Search(tmem.Pair{Source: "en", Target: "es"}, "The Parties shall …", 0, 0)
// hits[i].Source   最后一次写入时的原文原样
// hits[i].Target   译文
// hits[i].Similarity 相似度（整数）

err = s.Cleanup(time.Now()) // 删除 180 天前写入的条目
err = s.Close()             // 写快照并关闭
```

注意：调用方需将所有调用串行化（库内不做并发控制）。`Open` 会在宿主未自行设置
Go 运行时内存限制时将其设为 1600MB（`debug.SetMemoryLimit`），以保证百万级条目下
进程内存稳定在 2GB 以内；宿主已设置则尊重宿主。

## 设计

- **索引**：每个语言对一个索引。条目按规范化原文码点长度分桶（16 个长度一桶），
  桶内对码点三元组（trigram）建位置感知倒排索引（trigram 哈希 → 差分 varint 编码的
  升序 (条目id, 位置) 序列）。检索时依次做：长度过滤（`|L-l| ≤ ⌊max(L,l)(100-th)/100⌋`）、
  位置 q-gram 计数过滤（公共 trigram 数下界，必要条件的保守放松，只误留不误删）、
  候选精确有界编辑距离验证。结果与逐条暴力比对完全一致。
- **覆盖与清理**：墓碑标记，墓碑比例超阈值时原地压缩（重排 id、过滤倒排表）。
- **持久化**：`journal.log` 运行期追加日志（写入/清理按批落盘），`snapshot.dat`
  关闭时写全量快照（先临时文件再 rename）。打开时加载快照并回放日志。

## 测试

```sh
go test ./...        # 单元测试 + 与暴力参考实现的随机对照 + 持久化/重开
TMEM_PERF=1 go test -run TestPerfMillion -v .   # 百万级性能验证（约 5 分钟）
```

对照测试覆盖：极短原文、门槛 75/100、相似度正好落在门槛、长度差很大、中文与
阿拉伯文、混合空白、覆盖写入、清理之后、重新打开之后。

## 性能实测（Apple Silicon，100 万条/语言对，原文 20~300 码点，3000 词集中词表，大量近重复句）

- 写入：100 万条共 10.8s；单批 1000 条最大 27ms（要求 < 1s）
- 检索（3000 次）：p50 = 31ms，p95 = 69ms，p99 = 75ms（要求 p95 < 100ms）
- 内存：峰值 RSS 1.48GB（要求 < 2GB）
- 关闭 2.0s；重新打开 0.87s（要求 < 30s），200 条查询结果与关闭前完全一致
- 一年模拟（每天 5000 条写入 + 每晚清理，共 365 天，47s 跑完）：
  内存峰值 RSS 1.85GB 稳定不增长；之后检索 p95 = 69ms
